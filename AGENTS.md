# Правила работы над «Лавкой у моря»

Эти инструкции относятся ко всему репозиторию.

## Git

- Работать в `main`. Не создавать и не отправлять другую ветку без явного запроса пользователя.
- Detached worktree не разрешает создавать ветку: найти checkout `main` или организовать работу там без новой ветки.
- При запросе commit/push интегрировать изменения в `main` и отправлять `main`; сначала проверять рабочее дерево и состояние remote.
- Не удалять ветку с уникальными коммитами, пока нужные изменения не присутствуют и не проверены в `main`.

## Контекст проекта

- Начинать с README.md, docs/HANDOFF.md и docs/GAME_DESIGN.md. Они достаточны для продолжения без прежнего чата.
- docs/reference содержит архив исходных материалов; не изменять оригиналы ради новых решений. Новые решения отражать в текущей документации.
- Художественный ориентир: docs/reference/coastal-shop-approved-visual.png. Товары и рабочий UI должны оставаться отдельными элементами.
- Для каждой новой постройки сначала закреплять единую физическую модель: стены, проёмы, двери, окна, комнаты, проходы, оборудование и положение камер. Карта, фасад и все интерьеры обязаны изображать одно здание. При взгляде изнутри на фасад учитывать зеркальность расположения проёмов; мебель не закрывает входы и окна. Модель и проверку соответствия хранить в текущей документации.
- Все ресурсы приложения и исходники ассетов хранить внутри репозитория. Не привязывать проект к абсолютным путям пользователя, папкам Codex или внешнему серверу документов.
- Подтверждать каждую выдаваемую задачу воспроизведением решения. Исчерпание ограниченного поиска означает неопределённость.
- Сохранять закреплённую Definition вместе с seed и версией. Продолжение, помощь и перезапуск не должны незаметно менять исходную задачу.
- При изменении генератора учитывать версию и совместимость сохранений. Не считать длину найденного решения доказательством интереса или минимальной сложности.
- SDK и реальную монетизацию подключать отдельными этапами по docs/RELEASE.md. Не представлять гипотезы дохода или удержания как доказанный результат.

## Проверка

- Для изменений правил/генератора/сохранений выполнять `npm test`; перед сдачей изменения сборки — `npm run build`.
- UI проверять в браузере на desktop и ширине 360 px; фиксировать границы реально выполненных проверок в docs/QA.md.
- Размер всей папки dist должен оставаться ниже 80 000 000 байт. Скрипт сборки считает все файлы, включая worker и ассеты.
- Документация, reference материалы и исходные PNG не входят в dist. Сохранять полезные скриншоты в docs/screenshots, временные логи — в игнорируемом artifacts.
