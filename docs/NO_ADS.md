# Покупка без рекламных пауз

12 октября 2026 года. По последнему решению пользователя единственная покупка за реальные деньги — **«Без рекламных пауз внутри игры»**, постоянный товар `disable_ads`. Премиум, платные коллекции, сезонные дорожки и ограничения косметики этим решением не вводятся. Шесть существующих отделок по-прежнему покупаются за игровые монеты.

## Что подготовлено

- Настройки → «Без рекламных пауз»: одна покупка и восстановление. Цена и значок валюты приходят из каталога SDK; фиксированной цены в приложении нет.
- `src/no-ads.ts` получает `getPayments()`, каталог, постоянные права через `getPurchases()` и подтверждение `purchase({id: 'disable_ads'})`. Товар не расходуется через `consumePurchase`. Права не записываются в игровой Progress, localStorage или валюты.
- Повторное нажатие и закрытие окна во время оплаты блокируются. Отмена/ошибка не дают право; потерянный ответ проверяется повторным чтением платформенных покупок. Известное право сохраняется при временной ошибке восстановления.
- Для владельца отключён вызов рекламной паузы и запрашивается скрытие баннера. Неопределённое состояние прав тоже запрещает паузу. Покупка не меняет заказы, звёзды, ремкомплекты, монеты или закреплённую попытку.
- `src/yandex-platform.ts` сохраняет локальный режим и подключает платформенные события паузы/возобновления, LoadingAPI и GameplayAPI. Обычная сборка SDK не запрашивает. Целевая `npm run build:yandex` загружает `/sdk.js` на площадке.

**Ограничение:** SDK предоставляет интерфейс оплаты, но товар ещё не создан в консоли — это подтверждено пользователем. В локальной игре виден неактивный предпросмотр без цены и имитации платежа. На платформе предложение скрыто, пока каталог не содержит товар; уже купленное право восстанавливается даже после удаления товара из каталога. Настоящие деньги и облачный аккаунт не проверялись.

Новая автоматическая реклама в этой итерации не запускается. `showAdBreak()` подготовлен как общий шлюз для будущих размещений; сейчас игра не вызывает его после заказов. Подключение рекламных мест и проверка частоты остаются отдельным этапом RELEASE. Покупку нельзя запускать в продажу до работающих рекламных мест и платформенной проверки.

## Активация владельцем проекта

1. В консоли Яндекс Игр создать постоянный товар с точным ID **`disable_ads`**, названием и ценой. Активировать платежи и проверить, что товар присутствует в SDK-каталоге тестового проекта.
2. Собрать `npm run build:yandex` и загрузить содержимое `dist` на тестовую страницу Яндекс Игр. Локальный `npm run build` остаётся без загрузки SDK.
3. Настроить баннер для управления через SDK, если он используется. Все будущие рекламные паузы вызывать только через сервис прав; принудительные видео и внутренний баннер должны исчезать для владельца.
4. На площадке проверить настоящую тестовую покупку, отмену, повторные ответы, reload, восстановление на другом устройстве/аккаунте, ошибки и паузу/возобновление звука и ввода. Отдельно подготовить облачное сохранение Progress по RELEASE; платежное право уже читается из платформенного аккаунта.

Обещание пользователю относится к рекламе **внутри игры**. В окне явно исключён рекламный показ самой площадки при запуске. Видео за награду и x2 в игре не реализованы и в предложении не упоминаются. Граница покупки соответствует [требованию Яндекс Игр 1.13](https://yandex.ru/dev/games/doc/ru/requirements/1/13). Контракты проверены по официальным [покупкам](https://yandex.ru/dev/games/doc/ru/sdk/sdk-purchases), [рекламе](https://yandex.ru/dev/games/doc/ru/sdk/sdk-adv), [загрузке SDK](https://yandex.ru/dev/games/doc/ru/sdk/sdk-about) и [событиям игры](https://yandex.ru/dev/games/doc/ru/sdk/sdk-game-events); фактическая проверка на площадке остаётся обязательной.

## Проверка

`tests/no-ads.test.ts` проверяет сервис прав, восстановление, ошибки, повторные вызовы и запрет рекламы. `tests/ui/no-ads.spec.ts` проверяет настоящий интерфейс игры на desktop и 360 px с контролируемым SDK-стендом. Тестовая платформа имеет собственный фиктивный реестр; это не производственное хранение платёжных прав. `npm run test:platform` дополнительно проверяет целевую загрузку `/sdk.js`, готовность/паузу/возобновление и отказ SDK; команда использует стенд и оставляет платформенный `dist`. Для локального предпросмотра затем выполнить `npm run build`. Точные результаты и границы — [QA.md](QA.md).
