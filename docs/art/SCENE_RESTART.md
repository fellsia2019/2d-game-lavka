## Диагноз и направление

Нынешние интерьеры собираются из независимых картинок с разным ракурсом, светом и масштабом. Корзина дополнительно деформируется CSS matrix, передний край приближённо вырезается из её копии, игровые иконки товаров становятся интерьерной выкладкой. Координаты и проверка попадания кнопок в viewport не подтверждают художественную согласованность. Подпись только хлеба, CSS-коврик, мелкие корзинки и ящики возникли ради отдельных task ID, а не из потребностей композиции. На телефоне помещение при вписывании целиком получается слишком маленьким. Подробности независимого review Astra — [SCENE_AUDIT_VISUAL.md](SCENE_AUDIT_VISUAL.md).

Предлагаемое направление: компактная ортографическая диорама лавки. Один измеримый план комнаты, одна камера, общий свет и материалы; мебель строго вдоль двух осей стен. Закрытые основания шкафов дают силуэт; широкие встроенные лотки с низким передним краем удерживают товар. Меньше мелкой текстуры, крупнее понятные формы. Проход от двери и рабочий проход за кассой свободны. Категорийные таблички, декоративные цены, коврик и случайные предметы на полу исключены из концепта.

Цель — не заменить нынешний коллаж другим цельным JPEG. Будущие фон, мебель, заполнение, передние маски и контактные тени должны экспортироваться отдельно из одного пространственного источника. Товары головоломки могут иметь отдельные интерьерные ракурсы с сохранением узнаваемой формы и цвета. Это отдельные ресурсы, а не механическое увеличение иконок.

## Концепты и пространственный источник

Новый каркас — [scene-reset-camera-guide.json](concepts/scene-reset-camera-guide.json) и [PNG](concepts/scene-reset-camera-guide.png). Он построен скриптом [prepare-scene-reset-guide.py](../../scripts/prepare-scene-reset-guide.py), Pillow + NumPy. Комната 5×4 м, ортографическая проекция, оси пола ±30°; слои разрешены по глубине каждого пикселя, без сортировки длинной мебели по её середине. Это блокинг для обсуждения, не файл Blender и не готовая сцена приложения.

По каркасу встроенный ImageGen создал три состояния одного предложения:

- [До ремонта](concepts/scene-reset-before-v2.png): старые поверхности, помещение без оборудования.
- [После ремонта и установки мебели](concepts/scene-reset-middle-v2.png): пустые витрины, лотки и прилавок.
- [Заполненная лавка](concepts/scene-reset-finished-v3.png): витрины с товаром и касса, развёрнутая к рабочему проходу.

[Интерактивное сравнение](concepts/scene-reset-review.html) сохраняет просмотр концептов без изменения игрового сохранения. Реальная покупка, маски и мобильная камера теперь работают в игре; первый мастер использован как источник зарегистрированных товарных слоёв.

[scene-reset-v1-draft.png](concepts/scene-reset-v1-draft.png) — отвергнутый первый черновик. Ранние задания сохранены в [SCENE_RESTART_PROMPTS.json](SCENE_RESTART_PROMPTS.json), задания переноса и второго ракурса — в [scene-reset/PROMPTS.json](scene-reset/PROMPTS.json). PNG концептов не входят в dist; выбранные источники экспортируются в runtime WebP.

Плановый проход между передним краем северного лотка и выступом столешницы — примерно 1,185 м. Его удобство в реальной игре ещё не проверено; bitmap не является метрическим доказательством. Независимый review признал v2 подходящим для обсуждения направления. После него отдельно исправлен разворот кассы (v3), подготовлены две ранние стадии и мобильный кадр. Маски и послойная сборка остаются задачей переноса; эти изображения не являются доказательством корректности спрайтов.

## Технология и этап переноса

Фактический runtime — TypeScript/Vite, HTML/img/CSS. Canvas.js в зависимостях и отрисовке нет. Предлагаем сначала проверить один модуль из общего пространственного источника: корпус → пустой лоток → товар → точная передняя маска → контактные тени. Затем рассмотреть PixiJS/WebGL для сцен обустройства, оставляя правила, solver, worker, сохранения и рабочий UI в TypeScript/DOM. Выбор Pixi — инженерная рекомендация, а не результат замера прототипа. [Сравнение и контракт сцены](SCENE_RENDER_DECISION.md).

Unity Web технически возможен и официально поддерживает некоторые мобильные браузеры; перенос всей игры добавит отдельный runtime и интеграцию браузерной логики. Смена движка сама по себе не исправляет исходные ракурсы и маски. Unity или Blender можно использовать для авторства общей 3D-сцены с экспортом 2D. [Unity browser compatibility](https://docs.unity.com/en-us/engine/6000.0/manual/platform-specific/webgl/intro/browsercompatibility), [Pixi renderers](https://pixijs.com/8.x/guides/components/renderers).

Внедрение начнётся после принятия направления пользователем. Перед распространением на остальные комнаты нужен именно собранный модуль, совпадающий с эталоном на desktop и 360 px, включая заполнение крайних слотов, маски, смену состояния и сохранение покупки. Полный общий bitmap и отсутствие DOM-пересечений этого не заменяют.
