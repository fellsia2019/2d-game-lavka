# Передача проекта другому агенту

Обновлено **6 октября 2026 года**. Этот документ и связанные файлы достаточны для продолжения с другого устройства без истории чата. Работать в **main**. Перед commit/push проверить рабочее дерево и origin/main; не создавать другую ветку без запроса пользователя.

## 1. Принятая цель

Большая долгосрочная коммерческая **онлайн-браузерная игра для Яндекс Игр**, с desktop и браузерами телефонов. Бизнес-цель владельца — существенный заработок за счёт привлекательной игры, возвратов игроков, сезонных пропусков и добровольной рекламы. Отдельное мобильное приложение не требуется. Референсы восстановления и развития — **Homescapes и Gardenscapes**; наша головоломка — перенос товаров между полками и сбор троек.

Главный источник принятых решений — [CONTENT_MASTER_PLAN.md](CONTENT_MASTER_PLAN.md). Прочитать целиком перед продолжением. Данные — [full-product-plan.json](content/full-product-plan.json), каталог — [CONTENT_CATALOG.md](CONTENT_CATALOG.md). Реальное поведение — [GAME_DESIGN.md](GAME_DESIGN.md). При новой просьбе пользователя обновлять эти документы согласованно.

## 2. Объём и стадийность

Первый публичный выпуск — **6000 закреплённых проверенных заказов**, шесть локаций по 1000, шесть глобальных Stage, 36 локальных этапов, 756 работ и финал начальной кампании. На локацию: 80+120+160+200+220+220 заказов, 26+20+20+20+20+20 работ. Частичные производственные блоки не являются публичными релизами. Число заказов не доказывает время прохождения; сценарии 100–300 часов при 1–3 минутах — только арифметика.

Локации: **лавка, склад и поставки, большая лавка/фруктовый двор, пекарня, терраса, ресторан второго этажа**.

- Stage 1: лавка I → подготовка/постройка склада и склад I. Итого 160 заказов.
- Stage 2: на выбор лавка II, склад II, фруктовый двор I; после его I доступен II. Итого 440, накоплено 600.
- Stage 3: III первых трёх локаций и пекарня I–III. Итого 840, накоплено 1440.
- Stage 4: IV первых четырёх и терраса I–IV. Итого 1360, накоплено 2800.
- Stage 5: V первых пяти и ресторан I–V. Итого 1880, накоплено 4680.
- Stage 6: VI всех шести. Итого 1320, накоплено 6000.

Следующая глобальная стадия требует соответствующего локального результата всех уже введённых предприятий. Внутри текущей стадии проекты независимы; локальные этапы одной локации последовательны. `route` и глобальные номера в плане служат каталогу, не определяют обязательный линейный маршрут игрока.

## 3. Обязательный путь открытия территории

На карте изначально работает только исходная лавка. Новые места заброшены и заняты мусором, зарослями, лианами, пнями, поваленными деревьями или сгнившими хозяйственными остатками. При доступности проекта последовательность такая: мусор → разбор старого → растительность → деревья/пни → окончательная очистка/выравнивание → разметка → фундамент → каркас/стены → крыша → окна/дверь → отделка → свет/безопасный вход → базовое оборудование → внутренние заказы и развитие.

Каждый оплаченный шаг меняет отдельные слои карты/сцены и сохраняется. Новый склад строится на подготовленном участке; готовая старая складская картинка текущей карты не соответствует целевому поведению. Для террасы нужны опоры, настил, перила/ветрозащита и навес. Ресторан — очистка верхней площадки лавки, усиление, надстройка и лестница.

До входа и базового оборудования выполняются **новые строительные заказы в уже открытом здании**. Они имеют собственные orderId, относятся к строящемуся проекту и дают одну новую награду; старые повторы не финансируют обязательную стройку. В первом этапе нового здания 38 из 80 заказов относятся к подготовке/стройке/первому оборудованию, оставшиеся 42 — внутренние после четырнадцатой работы. Пристройка фруктового двора II — 72 проектных и 48 внутренних заказов. Цены входят в бюджет этапа, дополнительной платы за открытие нет.

## 4. Долгая жизнь продукта

До первого публичного выпуска должны работать ежедневные контракты, недельные проекты, коллекции и сезоны с бесплатной/платной дорожками. Ориентир сезона — 28 дней и 30 ступеней; пропуск покупается для одного сезона. Основные заказы тоже дают сезонный прогресс. Обязательная кампания доступна без оплаты и просмотра рекламы; помощь и оформление необязательны.

SDK, реальные платежи, облако и аналитика внедряются отдельными техническими этапами по [RELEASE.md](RELEASE.md), но входят в готовность полного продукта. Сезоны не откладывать из продуктового плана до неопределённого будущего. Удержание и доход пока не измерены; не обещать подтверждённую прибыль.

## 5. Что действительно реализовано

**Версия 0.5.0: 30 заказов, 11 покупок, два ракурса hall/cold, девять товаров.** Готовы две выкладки, прилавок, вывеска, холодная витрина, две корзины приёмки и холодные продукты. После заказа 20 можно перейти к витрине и заказам 21–30. Покупки нового блока после 24/26/30 стоят 4/2/4 ★. После всего готового контента экран показывает «Продолжение готовится» и повторы.

Плановые цели обновлены до 80 заказов/26 работ первого локального этапа и 1000/126 всей лавки. Готовые 30/11 не закрывают этот этап. **Ни первый блок 600, ни новая стройка, ни свободный выбор глобальных Stage пока не реализованы.** Большой плановый JSON и лёгкие runtime-цели не являются готовыми Definition, покупками или механиками.

Код всё ещё использует один CHAPTER, линейное открытие заказов, покупки только первой лавки и один активный Attempt. Будущие локации не имеют playable-каталогов. Это конкретный долг ближайшего блока; данные `requiresCompletedPhases` новой модели уже подготовлены.

Не путать конец доступной серии, завершение локального проекта, глобального Stage и всей кампании. Нынешние `allDone()/shopComplete()` проверяют первую лавку, а не весь будущий продукт. Их нужно заменить в общем управлении проектами; 30 готовых побед никогда не означают финал кампании 6000.

## 6. Сохранения и защита опубликованного начала

Ключ `coastal-shop:progress:v1`, schema **5**, campaign **coastal-campaign-3**, генератор **coastal-slice-3**. Миграции schema 1–4 сохраняют валюты, inventory, объекты, цвета и точную активную попытку. Новые задачи/награды миграция не начисляет. Старые 20 Definition остаются coastal-slice-2; 21–30 — coastal-slice-3. Нельзя подменять исходные раскладки новой генерацией.

Первые 20 нормализованных Definition закреплены из main 69f2332: SHA-256 `86ee2c26eb037d66215c99113bc355ecd684ff630a34bfe3f610766acfca8c0e`. Прежние пять покупок и затем восемь/одиннадцать опубликованных шагов сохраняют id и цены. Legacy-цветы и цвета остаются собственностью. Не удалять миграции как мусор.

Полная база из 30 Definition версии 0.5.0 закреплена для передачи: SHA-256 нормализованного JSON `f8c0083f5fa7d067823bde46ba2fb322f60c35e276648370fe28ae548a5ca39c`. Оба соответствия проверяются unit-тестом; изменение будущего плана не меняет исходные задачи.

Автоматическое обучение только в 1–3. С четвёртого подсказка — один ход по явной кнопке, затем акцент исчезает. Продолжение, reload и отмена не включают показ сами. Оплаченный кеш для того же состояния повторно показывается бесплатно по запросу. Помощь покупается в отдельном магазине за игровые монеты; применение отдельно, исходная задача решается без неё.

## 7. Следующая задача: один крупный блок

Реализовать **весь Stage 1–2: 600 заказов, 138 работ**, шесть проектов `shop-1`, `warehouse-1`, `shop-2`, `warehouse-2`, `fruit-yard-1`, `fruit-yard-2`. От текущей базы остаются 570 Definition и 127 работ. Не сдавать очередную самостоятельную прибавку 20–30 заказов вместо этой задачи.

Порядок работы:

1. Общая модель проекта, активной локации, доступности, глобальных стадий и строительного gate. `src/content.ts`, `campaign.ts`, `world.ts`, `main.ts`, worker/jobs и build-check сейчас знают только одну линейную главу.
2. Новая версия сохранения: выбранный проект, точные незавершённые Attempt по проектам, выполненные taskId и состояния стройки. Старый Attempt перенести без изменения, все цвета/валюты сохранить. При переключении ветви не уничтожать её незавершённый заказ.
3. Полная лавка I 80/26, карта заброшенных участков и слой каждого шага. Затем полный склад I с внешними проектными заказами, новым зданием, базовым оборудованием и внутренними заказами.
4. Настоящий Stage 2: лавка II и склад II доступны независимо; фруктовый двор I и пристройка II. Завершение ветви не требует сначала пройти другую ветвь текущей стадии.
5. Расширенные рецепты и ассортимент для 600 содержательных задач; закрепление/replay каждого решения и отбор структур. Новые правила версионировать вместе с solver/hints/storage; нынешние девять рецептов не подтверждают разнообразие большой кампании.
6. Проверить сквозной блок, несколько порядков выбора, отложенные покупки, все состояния стройки и reload, сохранение попыток, награды/покупки, desktop/360 px. Далее производить Stage 3–6 до полной кампании.

Проверки новичков и физических телефонов нужны перед выпуском; сейчас не останавливать расширение контента ради них. SDK и сезонная система строятся параллельными техническими направлениями, без реальных списаний до отдельного этапа.

- `docs/art/COLD_SHOP_PROMPTS.json`, `cold-art-manifest.json` и `scripts/prepare-cold-art.py` — реальные ресурсы холодного отдела. Пользовательские абсолютные пути и папки Codex не являются зависимостями проекта.

## 9. Запуск, проверка и выпуск

Node.js 22.12+, `npm ci`, `npm run dev` → http://localhost:5180/. Авторский инструмент `/author.html`, сцена `/campaign.html`. Production preview `npm run preview` → http://localhost:4173/. Сохранения разные для каждого origin; облако ещё отсутствует.

План: `npm run content:plan`; после изменения JSON — `node scripts/check-content-plan.mjs --write`. Эта команда проверяет арифметику/зависимости/финансирование, не будущие решения. `npm run content:produce-shop` воспроизводит закреплённую текущую серию, не создаёт 6000 заказов.

`npm test`, `npm run build`, `npm run test:ui`; при необходимости сначала `npx playwright install chromium`. UI-тесты идут на изолированном `127.0.0.1:4190`, не на пользовательском origin. Проверки и реальные ограничения — [QA.md](QA.md).

Весь dist <80 000 000 байт, цель полного продукта 64 МБ. Для 6000 Definition/путей заложено 18 МБ. Источники/документация вне dist; загрузка по проектам и ограниченный кеш обязательны. SDK, облако, рекламу, реальные покупки, локализацию и требования площадки перепроверять по [RELEASE.md](RELEASE.md) перед интеграцией.
