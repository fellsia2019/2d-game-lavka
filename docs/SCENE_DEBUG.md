# Быстрая проверка сцен

Кнопка **«Дебаг»** открывает обычное игровое окно без параметров URL. Из заказа остаются «Пройти уровень», «Заново этот уровень» и обычный список заказов. Автопрохождение выполняет проверенное решение обычными ходами; его правила и награды не меняются.

Из сцены вход: кнопка **«Дебаг»** в её нижнем левом углу; **Настройки → Дебаг** также сохранены. Во время заказа кнопка находится в верхней игровой панели.

Блок **«Сцены и прогресс»** позволяет сразу выбрать любой из восьми произведённых локальных этапов. Например, выбрать «Склад · этап 1», затем «С начала» и **«Применить и открыть сцену»**: лавка I завершится как обязательная предпосылка, откроется заброшенная площадка склада, кошелёк позволит покупать все 26 работ без прохождения 80 заказов. Для холодильного блока выбрать «Склад · этап 2»: автоматически завершатся только лавка I и склад I; независимые лавка II и фруктовый двор не покупаются.

Для пекарни путь такой: **Дебаг → «Сцены и прогресс» → «Пекарня · этап 1» → «Показать улучшение» → число 0–26 → «Применить и открыть сцену»**. `0 / 26` показывает начальную площадку; значения 1–26 выбирают конкретную работу и показывают её штатную покупку. Работы1–10 относятся к двору,11–19 — к входному торговому залу,20–25 — к рабочей кухне,26 — к открытию. Номер в выборе — новая позиция, семантические ID предметов не перенумерованы. Обязательные предыдущие проекты завершаются автоматически, чтобы не проходить прежние 600 заказов ради проверки сцены. «С начала» позволяет последовательно купить все 26 работ с подготовленным кошельком; «Этап пройден» задаёт полный результат 26/80.

Для проверки доступа к внутреннему заказу 39 выбрать улучшение **14 / 26** и зачесть **38 из 80 заказов**. Применение показывает и покупает лотки входного торгового зала `bakery-s1-t20`; только после его оплаты внутренние заказы доступны. При 38 зачтённых заказах и 13 работах они остаются закрыты. Это настройка тестового сохранения, а не подтверждение прохождения заказов обычным решением.

Пресеты сначала заполняют поля. Их можно изменить перед применением:

| Пресет | Выполненные работы | Зачтённые заказы |
| --- | ---: | ---: |
| С начала | 0 | 0 |
| Половина | Половина списка, округление вниз | Половина списка, округление вниз |
| Все работы | Весь список | 0 |
| Этап пройден | Весь список | Весь список |

Поле **«Показать улучшение»** позволяет выбрать любую работу — пол, стены, дверь/окно, прилавок и остальные. После «Применить и открыть сцену» все предыдущие работы готовы, показывается нужный полный ракурс до выбранной работы, затем она выполняется через обычную покупку с проявлением/светом/искрами. Финальная надпись и подтверждение не нужны: управление возвращается само. Пресеты с ненулевым числом работ показывают последнюю работу выбранного состояния; «С начала» открывает исходную сцену без покупки. Уже просмотренную работу можно показать снова.

Поле заказов отмечает первые N существующих канонических orderId выбранного этапа. У пекарни локальные номера 1–80 соответствуют плотным индексам загрузки **601–680**, а сохранённые `Definition.number` — каталожным номерам **1081–1160**. Плотный индекс не переписывает Definition. При применении сбрасывается **только его** открытая попытка, что прямо указано в окне. Попытки других проектов сохраняют Definition, seed, версию, appearance, поле, отмены, решение, подсказки и квитанцию награды. Перед визуальным показом кошелёк доводится до суммы работ, начиная с выбранной; больший существующий остаток сохраняется. Затем выбранная работа штатно списывает свою цену. Повторное применение не наращивает деньги. Монеты, помощь, настройки, цветовые предпочтения и приобретённое дополнительное оформление сохраняются.

Применение — сознательное изменение тестового сохранения. Оно не воспроизводит заказ, не выдаёт игровую победу, не начисляет 60 монет за отмеченный orderId и не отправляет событие победы. Отмеченный заказ при обычном повторном прохождении считается повтором. Возврат выбранного этапа к началу сохраняет уже приобретённые результаты независимых/последующих проектов; для полностью чистой кампании по-прежнему можно очистить сохранение.

Отдельный блок **«Добавить валюту»** пополняет звёзды, ремкомплекты или монеты на заданное число. Эта кнопка сохраняет открытый заказ без изменения его Definition и награды; подходит для проверки покупки на текущем экране. Отрицательные, дробные, пустые и небезопасные значения не применяются.

Текущий каталог содержит **760 заказов, 178 работ, 29 товаров и восемь проектов**. Старый блок Stage 1–2 остаётся 600/126; первая пекарня и терраса добавляют по 80/26. Полный Stage 3 ещё не завершён: пять непроизведённых проектов требуют 760 заказов/100 работ, они не появляются в выборе дебага.

Реализация: `src/debug-scene.ts`, `src/debug-scene.css`; чистые функции готовят изменение атомарно и не обращаются к storage, генератору или worker. Контроллер сначала готовит префикс до выбранной работы, переключает экран до закрытия игрового окна, сохраняет Progress обычным механизмом и вызывает `buyTaskWithReveal`. Это предотвращает обращение coaching к удалённой Attempt при применении из заказа. Текущие версии — **schema11 / `coastal-campaign-9`**; перенос schema 8 сохраняет кошельки без повторного перераспределения. Unit-проверки — `tests/debug-scene.test.ts`; только реально выполненные браузерные проверки фиксируются в [QA.md](QA.md).

При явном применении пресета пекарни старый `bakeryLegacyPrefix` удаляется, состояние строится по новой очереди. Отладка другого здания сохраняет его вместе с прогрессом/попыткой пекарни. Перенос schema9→11 не переигрывает покупки и не сбрасывает текущий заказ.

Терраса доступна в видимом дебаге без query-флага: выбрать `terrace-1`, число работ или конкретное улучшение. Для её открытия готовятся реальные предыдущие проекты до пекарни включительно; остальные сохранённые попытки остаются по прежним правилам. Все 26 покупок показываются в цельном виде «Терраса у моря».
