# Подготовка и добавление контента

Версия 0.2.0 имеет законченный цикл главы. Новые материалы добавляются через каталог и проверку, без зависимости от прошлого чата. Основные правила — GAME_DESIGN.md; фактические проверки — QA.md.

Перед массовым наполнением остаются проверки на реальных телефонах и новичках, а также автоматические проверки UI. Эти задачи перечислены в [HANDOFF.md](HANDOFF.md); они не закрываются воспроизведением заранее известного решения.

## Мастерская

После npm run dev открыть http://localhost:5173/author.html; для production preview — http://localhost:4173/author.html. Это отдельный инструмент автора, без изменения игрового прогресса.

1. Выбрать рецепт и seed. «Создать раскладку» генерирует кандидата в worker, проверяет его и воспроизводит решение до победы. Последние 12 точных структур страницы исключаются; при перезагрузке история мастерской очищается.
2. Сравнить число товаров, типов, полок, свободных мест, задних рядов и замков. Найденные ходы не считать рейтингом сложности. Пройти поле самостоятельно, затем нажать «Заново» и воспроизвести «Шаг решения» до сообщения «Заказ готов!».
3. При ручных переносах исходный пошаговый путь отключается до «Заново». Исходная Definition остаётся прежней; экспорт не записывает случайное текущее поле вместо исходной задачи.
4. JSON можно редактировать или импортировать из файла до 100 КБ. После правки нажать «Проверить JSON и открыть». Недопустимые метаданные, товары, размеры рядов, замки или невоспроизводимое решение блокируют экспорт.
5. «Скачать проверенный JSON» ещё раз проверяет и воспроизводит путь. Для возвращения к уже выбранной задаче импортировать сохранённый файл; исключение повторов может выбрать другой кандидат даже с прежним seed.

Экспорт — подготовленный файл, а не автоматическая публикация в главу. Включение в каталог остаётся явным изменением репозитория и проходит build.

## Новый заказ

Исходные проверенные Definition первой главы находятся в **src/levels/chapter.json**. Каталог и порядок — в **src/content.ts / CHAPTER**. Игра клонирует Definition по стабильному id; при запуске не перегенерирует главу по seed. Генератор используется в мастерской и для подтверждённых будущих задач.

1. Сохранить выбранный экспорт. Назначить новый стабильный id, например morning-market. Он обозначает конкретный заказ, не версию генератора и не номер в списке. Уже выпущенный id не переиспользовать для другого заказа.
2. Добавить Definition в массив src/levels/chapter.json. Обновить id и number; сохранить shelves, seed, generatorVersion, recipe и verifiedSolution выбранного кандидата.
3. Добавить запись в CHAPTER с тем же id и profile и коротким name. customer и line остаются метаданными; обязательный сюжетный текст на игровом экране не показывать. number в игре определяется текущим порядком каталога. При необходимости указать lesson: transfer / tools / rear / crate. Обучение объясняет действие подсветкой нужной ячейки, а не абзацами текста; переносам обучать только на подходящей ручной задаче.
4. Обновить CONTENT_VERSION. Отрегулировать цены ремонта, если меняется длина главы. Фиксированный LEGACY_IDS не пересчитывать из новых seed и порядка: это таблица уже выпущенных сохранений.
5. Выполнить npm test и npm run build. content:check требует ровно одну Definition на запись, уникальные id и структуры, воспроизведённые решения, локальные ресурсы и достаточное число звёзд для ремонтов. Структурный повтор требует осознанного нового решения и изменения политики проверки, а не случайного отключения gate.
6. Пройти новую задачу через браузер, включая результат/следующий экран и повтор, на desktop и ширине 360 px. Зафиксировать проверки и снимки в docs/QA.md и docs/screenshots.

Редактирование shelves требует нового проверенного пути. Координаты хода — [[полка, место], [полка, место]], индексы с нуля. В текущем формате обычный передний ряд — три элемента; rear — массив рядов по три. null — пустое место; unlockAfter — положительное количество отправок. Резерв создаёт помощь, он не включается в исходную Definition. Валидатор допускает 1–6 обычных полок, до двух задних рядов на полке, до четырёх типов товаров одновременно, путь до 100 ходов, непустые метаданные до 200 символов. Основная глава использует budget: null.

## Новый товар и ремонт

Товары регистрируются в src/catalog.ts: стабильный короткий ключ, название, локальное имя файла и цвет. Добавить transparent WebP в public/assets и исходный PNG в docs/art с происхождением/заданием в ASSETS.md. Все проверки используют единый реестр; нельзя добавлять скрытый товар только в UI. При изменении набора, из которого выбирает генератор, повысить VERSION и повторить npm run content:audit. Закреплённые JSON и сохранения сохраняют свои исходные товары/версию; удаление выпущенного ключа требует миграции.

StructuralKey перебирает перестановки типов. Текущие рецепты используют 2–4 типа, реестр содержит 6; увеличение числа одновременно участвующих типов требует проверки производительности и worker лимита. Не расширять бесконтрольно только ради количества ассетов.

Ремонты задаются в src/renovations.ts по порядку покупки; новый тип требует своего слоя sceneHTML, предпросмотра, доступного действия и завершённого результата. Для нового типа сохранить совместимость schema или добавить явную миграцию. Build проверяет стоимость всех узлов против количества новых звёзд. Изменение каталога без изменения генератора не требует смены версии генератора.

## Проверка серии и наблюдения

npm run content:audit проверяет seed audit-0…audit-99 каждого профиля без истории исключений и пишет docs/generator-report.json. Эта выборка измеряет проходимость и точные повторы, не интерес и не верхнюю границу всех seed. Ограниченный поиск без решения означает unknown; не выдавать такого кандидата игроку. Проверенный путь не считается кратчайшим.

Для наблюдения на игроках запустить игру с ?playtest=1. В настройках доступен экспорт последних 1000 событий **с момента этой загрузки страницы**. Журнал не отправляется на сервер и очищается перезагрузкой. Записать первый самостоятельный перенос, понимание рядов/замков, ошибки, время и выходы. Автоматическое прохождение по известному пути не доказывает понятность новичку.

Перед платформенным выпуском выполнять этапы RELEASE.md. SDK, реклама, платежи и облако не входят в процесс простого добавления контента.
